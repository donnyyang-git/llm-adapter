LLM Adapter

本機 Gemini 對話保存器架構概覽

本專案使用「本機受控 Chrome + Python 後端 + 狀態機 + 本地存檔」的設計，把雲端對話流程轉成本地工作流，目的在於保留歷史、降低風險、避免污染日常 Chrome 與日常登入狀態。

系統架構圖

各元件簡要說明

使用者瀏覽器

開啟本機網站，透過 HTML / JS / SSE 操作 Chrome 狀態、選擇分頁、送出問題與觀察結果。

FastAPI App

統一處理 API、事件串流、狀態協調與路由，讓前端與底層自動化邏輯彼此隔離。

ChromeManager

管理專用 Chrome 啟動、CDP 偵測、loopback fallback、profile lock 清理，以及 tab 列表更新。

專用 Chrome

使用獨立 profile，避免接管日常使用的 Chrome，並保留 Gemini 登入狀態。

GeminiAdapter

負責定位輸入框、判斷生成狀態、透過網頁版操作 Gemini，並抓取回覆內容。

ConversationService

處理一次對話的生命週期，管理 pending / generating / completed 等狀態與 tab 鎖。

ConversationStore

將 session 保存成 JSON 與 Markdown，確保歷史資料可讀、可回溯且可原子寫入。

設計原因： 這種分層方式可將風險收斂：Chrome 問題、Gemini 網頁變動、狀態機錯誤、資料保存錯誤能分別由不同模組負責，調試與維護都更加清楚。

近期互動式 Artifact 能力

多 artifact 回覆

單一 Gemini 回覆可拆成多個 artifact 保存，不再假設只會有一段程式碼。

Monaco 程式碼擷取

Gemini 的 code panel 會從 Monaco model 擷取完整內容，降低 HTML / JS 缺段風險。

Code / Preview 切換

前端會在每個 artifact 卡片上顯示程式碼與預覽切換，但只有 HTML artifact 才會提供 preview。

本地附圖保存

Gemini 回覆卡片截圖保存於 data/conversations/_artifacts，方便回看原始畫面與輸出佈局。
