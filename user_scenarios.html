LLM Adapter 使用者角度操作範例

這份頁面以「圖例 + 流程」方式說明使用者如何在本機環境中啟動 Chrome、切換 Gemini 分頁、發問與保存對話。

首次啟用

新使用者的開場流程

🧭 啟動服務 開啟本機網頁
→
🌐 連接 Chrome 建立專用 profile
→
🔑 登入 Gemini 在專用瀏覽器中
→
💬 開始對話 選分頁並開始紀錄
1

在專案目錄啟動後端，打開本機入口，進入 LLM Adapter 主頁面。

2

點選 Connect Chrome，系統會啟動專用 Chrome 並避免污染原本的日常瀏覽器登入狀態。

3

在專用 Chrome 中登入 Google / Gemini，並開啟 Gemini 頁面。

4

返回本機介面按 Refresh，選擇正確的 Gemini 分頁，接著建立本地紀錄開始對話。

這個流程的核心，是「把一個專門的瀏覽器與本地會話連動起來」，讓使用者不會感到混亂，也能保留每次對話紀錄。

日常工作

實際提問與追蹤流程

📋 選分頁 挑選目標會話
→
📝 建立紀錄 開新 local record
→
⚙️ 送出問題 pending → generating
→
✅ 完成回覆 保存並顯示結果
1

在頁面上選擇對應的 Gemini 分頁，確認該分頁就是你要繼續的會話。

2

點選建立新本地紀錄，等於為這一輪會話開一個可追蹤的本地工作區。

3

輸入問題後，系統會顯示狀態：pending → generating → completed。

4

回覆完成後，可直接在本機介面查看內容，也可複製原文、匯出紀錄或回顧歷史。

這個畫面讓使用者能直接感受到每一次互動的狀態變化，並不需要自己去追目前是「送出中」還是「已回覆」。

常見操作場景

  • 研究整理與資料梳理
  • 程式碼問答與除錯
  • Prompt 比較與案例測試

畫面上重要資訊

  • 會話狀態
  • 每輪時間資訊
  • 回覆內容可複製
  • artifact 的程式碼 / 預覽切換
  • 紀錄可保留於本機

Gemini Artifact 呈現

  • 若 Gemini 產出多段程式碼，畫面會拆成多個 artifact 卡片。
  • 每個 artifact 可顯示自己的摘要與程式碼。
  • 只有 HTML artifact 才會顯示預覽，避免空白 preview 誤導使用者。
歷史回看

回顧與繼續工作

🗂️ 選舊紀錄 從 Saved conversations
→
🔎 檢查內容 查詢歷史與時間
→
🔁 回到會話 切回正確分頁
→
📌 繼續工作 接新問題或整理內容
1

如果該會話和當前 Gemini 分頁不一致，系統會提醒或切成唯讀模式；若左側重新選到同一個 Gemini tab，右側也會自動載入對應 session。

2

如果該會話和當前 Gemini 分頁不一致，系統會提醒或切成唯讀模式，避免錯誤接續。

3

需要繼續工作時，重新切回正確的分頁，保持上下文一致，然後接續新問題。

4

重新整理頁面後，系統會嘗試恢復先前的狀態，讓工作流更順暢。

這種設計的目的是讓使用者不會誤把舊對話接到錯誤分頁，避免歷史紀錄失真或上下文混淆。

回顧的價值

  • 可以快速回溯問題與答案
  • 能看到每輪的時間節點
  • 可比較不同版本的思路

使用者心智模型

  • 開啟服務 → 連 Chrome → 選分頁
  • 開始對話 → 追蹤狀態 → 完成回覆
  • 回看歷史 → 重新接續 → 保持連續性
