Gemini 本地對話保存器

完全掌控個人 AI 對話紀錄，自動化擷取與本機結構化備份方案

1. 解決痛點與核心目的

高價值對話易遺失

雲端平台雖方便，但隨時面臨紀錄搜尋困難、備份不易或帳號存取風險。

避免高昂 API 費用

直接透過自動化瀏覽器調用 Gemini 網頁版免費額度，無需付費 API Key。

完全掌控數據資料

所有對話紀錄雙向落盤為 JSON 與 Markdown。

結構化資料儲存

完整保留程式碼片段（Artifacts）、表格與 Markdown 語法格式。

2. 產品定位與限制

  • 架構規範：全純 Python 技術棧（FastAPI + Playwright），免去複雜的前端 Node.js 建置。
  • 單機安全部署：服務僅監聽 127.0.0.1，不開啟外部區域網路存取。
  • 獨立 Chrome Profile：接管專用 Chrome 視窗，避免存取或洩漏使用者日常瀏覽器的 Cookies/憑證。
  • 單一對話鎖定：針對同一分頁實施排隊與互斥鎖，保證對話傳送與擷取的穩定性。

3. 系統整體架構

前端介面 (原生 HTML/JS) ↔ SSE 即時事件串流 ↔ FastAPI 後端

核心服務元件：

  • ChromeManager：維護專用 Chrome 啟動與 CDP (遙控通道)連線。
  • GeminiAdapter：DOM 元素定位器與文字擷取核心。
  • ConversationService：對話狀態機與請求排隊。
  • ConversationStore：JSON & Markdown 原子寫入。
[Frontend]
   ↓ (HTTP / SSE)
[FastAPI App]
   ├─ ChromeManager → [Dedicated Chrome]
   ├─ GeminiAdapter → [Gemini Web UI]
   └─ Store → [data/conversations/]

4. 核心執行流程

  1. 啟動專用 Chrome：載入獨立 Profile，使用者手動完成 Gemini 登入。
  2. 選擇目標分頁：於 UI 介面重新整理並選取目前的 Gemini 聊天頁面。
  3. 送出問題（Pending）：將問題寫入本地暫存檔，鎖定該分頁工作狀態。
  4. 等待並監聽回答（Generating）：即時將生成內容透由 SSE 推送至 Web UI。
  5. 回答判定完成（Completed）：檢測生成停止按鈕消失與內容穩定後落盤。

5. 核心元件：ChromeManager & Adapter

ChromeManager

  • 自動尋找系統 Chrome 執行檔。
  • 帶入獨立 user-data-dir 與 CDP Port。
  • 提供 stable tab ID 映射供 API 呼叫。

GeminiAdapter

  • 優先使用 ARIA Label 與 Role 選擇器。
  • 監控 Gemini 輸入框、傳送與停止按鈕。
  • 擷取 Monaco Editor 內的完整 Code Artifacts。

6. 核心元件：ConversationStore

採用雙格式同步儲存 + 原子寫入（Atomic Write）機制，防止中斷損毀：

  • JSON Format：提供完整的對話元數據（Metadata）、輪次狀態（Turn status）及時間戳記。
  • Markdown Format：方便人類閱讀、知識庫整合與筆記軟體（如 Obsidian）直接調用。
  • 檔案結構： 
    data/conversations/
  ├── .json
  ├── .md
  └── _artifacts//.png

7. API 端點規劃示例

基於 FastAPI 提供簡潔且規範化的 RESTful API：

POST /api/chrome/start          # 啟動或重連專用 Chrome
GET  /api/tabs                  # 列出專用 Chrome 目前分頁
POST /api/tabs/select            # 選取指定的 Gemini 分頁
POST /api/sessions               # 建立新對話 Session
POST /api/sessions/{id}/messages # 傳送問題至指定 Session
GET  /api/sessions/{id}/events   # 建立 SSE 即時內容推送串流
